# Revision v0.5 — 2026-10-29

## Why

Starting F01 under v0.4 showed that the spec imported the whole predecessor tree (201 files) in one
node, with its history behind a merge commit, and changed it afterwards. The owner's model is
different: **write the tests, then port in the code needed to pass them.** Under v0.4, F01's tests
mostly checked the copy (hashes, dropped files, disabled workflows) rather than behaviour, and
F01-AC-4's grep for dropped paths contradicted the rule that imported files stay verbatim.

## What changed

- **SPEC §0, §2.2:** each node writes its tests, then ports the predecessor code they need. A node's
  fast tests stay in the lane, so a rule set early (no AWS, SHA-pinned actions, the builder by digest)
  holds for code ported later.
- **`docs/capabilities.md` (new):** every capability, the node that owns it, and whether it is ported,
  fixed, built, replaced or dropped. It accounts for all 201 predecessor files and replaces
  `IMPORT.md`.
- **SPEC §4.2:** path owners follow the ledger instead of F01.
- **SPEC §10, §11:** OD-11 is gone. The predecessor's history stays in the predecessor; a porting
  commit names its sources as `path:line` at `b9f533b`. No merge-commit exception.
- **F01 (renamed `fast-lane`):** `make test`, `pr-validate.yml` in the parity form, SHA pinning,
  Dependabot, CODEOWNERS, `.gitignore`, and the predecessor's agent guide. No bulk import, no
  disabled workflows, no `IMPORT.md`.
- **I01:** a standing no-AWS check plus the `REGISTRY` variable. Each porting node leaves S3 out of
  what it ports; I01's table says which. Its binpkg-store criteria moved to B01 (B01-AC-17, -18).
- **R01:** ports all of `monolith-base` with its nine tests before B01. The os-release URL moved to
  B03 (B03-AC-8); the `versions.lock` line to B01.
- **B01:** ports the distribution policy and the overlay packages `world` needs, the kernel as it is;
  depends on R01.
- **B02:** depends on B01 and changes the kernel B01 ported; the inline module checks of `build.yml`
  become `scripts/verify-kernel-modules.sh` (B02-AC-8), and B02-AC-9 forbids `configs/kernel.config`.
  Its slow criteria run locally in the builder image.
- **I03:** the `build.yml` and `attestation.sh` edits moved to B03 and S01, held by I03's test.
- **O01:** ports the manual QEMU targets as `test-bios` and `test-uefi` (O01-AC-6).
- **M01, M02, P03, R03, R05, G01, S01:** wording for what they port versus change.
- **Plan:** the MS1 chain is F01 → I01 → I02 → B01 → B02 → B03 (six nodes; twelve lead to MS1).
- **Tooling:** the `/node` skill and role agents check ported files against their `b9f533b` blob
  instead of `IMPORT.md`. A predecessor test ported verbatim may fail RED only because its subject is
  not ported yet.

## Correction, same day: tests come from criteria, not from the predecessor

The owner rejected the tooling rule above that let a predecessor test, ported verbatim, fail RED
with `No such file` naming its missing subject. That is a test that looks for a file, not test-first
development. Tests are written from criteria that say what the code does, and then only the code
that passes them comes in.

- **SPEC §0, §2.2, §7:** predecessor tests are not ported. Their cases go into the acceptance
  criteria of the node that ports the code they test, and that node's tests are written from those
  criteria. A test runs its subject; checking that a file exists is not a test.
- **R01:** new criteria AC-7 to AC-15 state what `monolith-base` does: help, `monolith-net`, the
  router's NAT and DHCP, `monolith-persist`, persistence at login, the clock tools,
  command-not-found and the installed paths (AC-15, slow, in the builder image). AC-6 is now only
  the lint lists. Size S becomes M.
- **B01-AC-9:** the prune predicate and savedconfig marker behaviour, instead of "the ported tests
  pass". B01-AC-13 adds `nftables` in `world`.
- **B02-AC-7:** the driver-tier symbols, listed. New B02-AC-10: `verify-resolved-i2c-off.sh`.
- **B03:** new AC-10 (`pcf-fontname.py`) and AC-11 (network and router wiring, checked in the built
  rootfs instead of by grepping scripts).
- **O01-AC-1:** the launch-retry decision; **I02-AC-4:** adds `--source-only`.
- **Ledger:** a predecessor test under **Source** is the origin of criteria, not a ported file.
- **Tooling:** RED fails on the behaviour a criterion states. A shell error, `No such file` from a
  missing subject, a file-existence check or a predecessor test copied whole is not a valid RED.

## Second correction: port the tests first

The owner corrected the first correction. The predecessor's tests hold verified knowledge, so they
are ported, not rewritten from criteria. Preserve proven code and its tests; apply test-first
development to the port and to every change.

- **SPEC §0, §2.2:** six steps per node: port the tests (harness and path adjustments only, listed;
  a case a criterion changes is changed and listed), add tests for uncovered criteria while keeping
  all existing coverage, RED (a missing implementation is a valid failure when the harness runs to
  its end and reports it as `FAIL`), port the code (changed only where a criterion requires), GREEN
  without touching RED tests, independent review. A baseline runs the RED tests against `b9f533b`'s
  implementation where practical: inherited behaviour passes, criteria of numbered changes fail.
- **SPEC §7, §9, §11:** the 21 predecessor tests are ported first by their nodes. The node template
  gains a required **Tests** section (ported first, added, baseline), and `check-spec.py` requires it.
  A ported test differs from its blob only by its listed adjustments.
- **Nodes:** all 22 have a **Tests** section. The predecessor tests are back in the *Ports from* lines
  of R01, B01, B02, B03, O01 and I02, ahead of the code. The behaviour criteria added by the first
  correction stay, verified by the ported tests (R01-AC-12 and -13 by the predecessor's own files).
  B02-AC-7 is verified by the three ported tier tests, with their `cfg=` line as a path adjustment.
  B03-AC-11 is the ported wiring tests plus the built-rootfs check. Named adjustments:
  `savedconfig-cache.test.sh` reports a missing savedconfig as `FAIL`, not `SKIP`; `pcf-fontname.test.sh`
  and `boot-test-retry.test.sh` report a missing subject as `FAIL`, not a traceback; the `401`
  benign cases of `binpkg-store.test.sh` become fatal (B01 change 14). S01 ports the CVE-gate canary
  first.
- **Ledger, AGENTS.md, plan:** tests are ported first.
- **Tooling:** the `/node` brief carries the **Tests** section and a coverage map; RED checks the
  ported tests against their blobs and that no ported case was lost; a baseline step runs the RED
  tests on `b9f533b`'s implementation; review checks coverage, implementation changes and that the
  RED tests are unchanged.

## Third revision: a verifiable migration, Make as the interface, a stronger release gate

The owner asked that the new repository build on the predecessor's engineering instead of repeating
it, with the smallest changes that finish the migration spec.

- **Migration ledger.** New `docs/migration.tsv`: each of the 201 files at `b9f533b` with its mode,
  blob, node, disposition (port, port+fix, replace, drop) and destination, plus the later nodes
  that change or move it. New `scripts/check-migration.py` proves completeness offline: the rows
  rebuild the predecessor's tree hash `d12a8f42…`. A `port` row no later node changes must keep its
  blob once landed, `--node <ID>` checks a node's files are in place, and `--all` checks the whole
  migration. `check-spec.py` runs it, and F01's `make test` will too. Provenance lives in the
  ledger and Git history; source files get no "ported from" comments, and porting commits name
  paths instead of `path:line`. Changing a ledger row is a spec change.
- **Make is the interface (SPEC §7).** Operations are Make targets backed by scripts; workflows only
  call them. `make test` is the whole PR check and the only step of `pr-validate.yml`; it now also
  runs `toolbox/ci lint` and the ledger check (F01-AC-1 to -4). The parity claim is narrowed:
  `toolbox/ci run` is a convenience that runs `run:` steps in one shared checkout, not an Actions
  emulator, so separate runners and artifact or cache transfers are shown only in CI. The `/node`
  slow-tier order, AGENTS.md, the role agents and the `toolbox/ci` docstring follow. No code in
  `toolbox/ci` changed.
- **Release gate.** G01 and R02 move to the critical track and P01 depends on both (17 critical
  nodes). G01's `persist-init`, `entry` and `smoke` modes gate the first release (new P01-AC-12).
  SLIP, PPP and dropbear may leave the README and be tracked instead, so serial networking does
  not hold the release (G01 change 2). R02's scan is `make overlay-qa`, run on every PR and on the
  tagged commit; it pulls the tree, so it is slow tier, not part of the offline `make test`.
- **Dashboard and browser demo** stay dropped, with no preservation machinery; the ledger's count of
  `web/` files is corrected from 11 to 13.
- **Hardware.** The i486 constraint no longer claims more than its checks show; the post-486
  instruction scan and 8 MB of RAM are future work in SPEC §10, with no node. The stale pointer
  from the i486 row to G01 is gone.

## Fourth revision: `make test` is the one testing interface

The owner asked for one testing interface with no fast/slow split: tests differ in runtime and
prerequisites, not in kind.

- **SPEC §7** is now "Oracle and tests". `make test` runs every test and builds or fetches what each
  needs; no test is skipped for a missing prerequisite. Make runs on the host, and each target uses
  the toolbox or the builder image itself. `make test` is the union of `test-lint`, `test-unit`
  (F01), `test-revbump` (R04), `test-overlay` (R02), `test-boot` (O01), `test-artifact` (O02),
  `test-gates` (S01) and `test-repro` (P02), each runnable alone. Until B03 builds an ISO, the ISO
  targets default to rc1's, behind its sha256; B03 makes the built ISO the default (B03 change 10).
  CI calls these targets and holds no test logic; a test step in a workflow is always a Make target.
- **The *Tier* field is gone** from all criteria and from the template; `check-spec.py` now rejects
  it. A criterion's *Verify* says how it runs. The `/node` skill's step 5 covers criteria verified by
  a build, a boot or a CI run.
- **F01** is renamed `make-test` (`nodes/F01-make-test.md`, test `make-test.test.sh`). `pr-validate.yml`
  runs `make test-lint test-unit`; R04 adds `test-revbump` (with the PR base as `BASE`) and R02 a
  second step, `make test-overlay`. No PR-check step runs a check outside Make.
- **O01** runs the boot modes with the toolbox's pinned QEMU, OVMF and pexpect through
  `make test-boot`; the `pip install` steps and `boot-test-requirements.txt` are gone (O01-AC-2, new
  -AC-7). The predecessor's interactive `make test`/`test-uefi` become `run-bios`/`run-uefi`.
  **O02** takes `scanelf` from the toolbox and adds `make test-artifact` (new O02-AC-8). S01 and P02
  add `test-gates` and `test-repro` (S01-AC-8, P02-AC-8). G01's host tools come from the toolbox.
- **`check-migration.py`** checks modes, from the git index or the file, wherever a ported file
  exists, and at `--node` the blob of every `port` row of that node, not only existence. F01-AC-2
  adds a fixture whose mode or blob differs.
- **B01:** the `401` cases belong to `binpkg-store.test.sh`; the `SKIP` adjustment to
  `savedconfig-cache.test.sh`.
- **G01:** a smoke exclusion is `covered` (naming a mode, a test file or a consumer atom with its
  own `run` row) or `untestable` (with a reason); a bare `n/a` fails (G01-AC-6).
