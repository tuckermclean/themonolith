## Purpose
rc1's kernel unpacks itself at the 16 MB mark (`CONFIG_PHYSICAL_START=0x1000000`), so a machine needs about 26 MB of RAM just to start it, and it holds 8 MB once running. Its 2.9 MB initramfs is mostly storage-controller modules that a 486 never loads. After this node the same main kernel, on every machine, loads at 1 MB, carries only what a CD boot needs built in, and holds about 5 MB. The initramfs is split, so an ISOLINUX `lowmem` entry boots the base archive alone. A `lowmem` boot mode proves a shell at 16 MB under `-cpu 486`, and every existing mode still passes with the concatenated initramfs.

## Standard mechanism
- **Kernel:** kbuild. `scripts/config` applies change 1 to the committed savedconfig, then `make olddefconfig` resolves it (B02's `menuconfig-kernel` path, `output/kernel.config.new`), and the result is committed as the savedconfig. B02's savedconfig marker rebuilds the kernel. No ebuild changes.
- **Initramfs:** the Linux initramfs format accepts concatenated compressed cpio archives, and the kernel unpacks them in order (`Documentation/driver-api/early-userspace/buffer-format.rst`). The ported `build-initrd.sh` writes two archives instead of one, each with its deterministic cpio options (P02).
- **Boot menu:** an ISOLINUX `LABEL`, as the others in `build-iso.sh`.
- Custom code: none new. One mode in `boot-test.py`, as G01's, and one test, `scripts/tests/lowmem.test.sh`.

## Changes from the port
1. **The kernel config.** On the savedconfig as M04 leaves it (6.12.y), with `scripts/config`, then `olddefconfig`:
   - load at 1 MB: `PHYSICAL_START=0x100000`, `PHYSICAL_ALIGN=0x100000`, `RANDOMIZE_BASE` off;
   - off, as compile-time features a live CD does not use: `FTRACE`, `KPROBES`, `UPROBES`, `BPF_SYSCALL`, `BPF_JIT`, `IO_URING`, `KALLSYMS`, `AUDIT`, `PROFILING`, `PERF_EVENTS_INTEL_UNCORE`, `PERF_EVENTS_INTEL_RAPL`, `PERF_EVENTS_INTEL_CSTATE`, `PERF_EVENTS_AMD_UNCORE`, `SLUB_DEBUG`, `SCHED_DEBUG`, `NET_SELFTESTS`, `ETHTOOL_NETLINK`, `EISA_NAMES`, `X86_MCE`, `BASE_FULL` (so `BASE_SMALL=y`); `LOG_BUF_SHIFT=14`, `LOG_CPU_MAX_BUF_SHIFT=12`;
   - built-in drivers become modules (`=m`): `EXT4_FS`, `EXT2_FS`, `9P_FS`, `NET_9P`, `NET_9P_FD`, `NETFS_SUPPORT`, `VIRTIO`, `VIRTIO_PCI`, `VIRTIO_CONSOLE`, `VIRTIO_INPUT`, `HW_RANDOM_VIRTIO`, `SCSI_VIRTIO`, `HYPERV`, `HYPERV_STORAGE`, `HYPERV_KEYBOARD`, `VMWARE_PVSCSI`, `PTP_1588_CLOCK`, `PTP_1588_CLOCK_KVM`, `USB`, `USB_HID`, `HID`, `HID_GENERIC`, `PPP`, `SLIP`, `VORTEX`, `R6040`, `BLK_DEV_RAM`, `CHR_DEV_SG`, `INPUT_PCSPKR`, `GAMEPORT`, `GAMEPORT_NS558`, `SERIO_SERPORT`, `SERIO_PCIPS2`, `ACPI_AC`, `ACPI_BUTTON`, `ACPI_FAN`, `ACPI_BATTERY`, `ACPI_THERMAL`, `HW_RANDOM`, `HW_RANDOM_INTEL`, `HW_RANDOM_AMD`, `HW_RANDOM_GEODE`, `HW_RANDOM_VIA`, `FIXED_PHY`, `REALTEK_PHY`, `MII`, `NET_FAILOVER`;
   - still built in, because the CD boot needs them: `BLK_DEV_LOOP`, `SQUASHFS`, `ISO9660_FS`, `OVERLAY_FS`, `ATA` and the IDE host drivers, `BLK_DEV_SR`, the AT keyboard (`KEYBOARD_ATKBD`), `FB_VESA`, `ACPI` and `EFI`.

   `MICROCODE` stays as `olddefconfig` leaves it (the issue's `-d` did not stick). A symbol of the lists above that `olddefconfig` sets back (a `select` from a built-in symbol, say) is named in the node PR with the Kconfig line that forces it. `olddefconfig` with the current builder may also turn on `I2C`: B02's `verify-resolved-i2c-off.sh` decides, and the fix is B02's (force the selecting option off, T-ddc-i2c-escalation), never a weaker check. The node PR records `vmlinuz`'s size and the boot line's memory figures (kernel code, rwdata, rodata, bss) against those of the kernel before the change. *AC-1, AC-2.*
2. **OD-8 and KALLSYMS.** OD-8's answer (issue #130): `9P_FS`, `NET_9P`, `NET_9P_FD` and `NETFS_SUPPORT` move from Tier 0 to Tier 2 (`=m` on the squashfs); 9p serves only QEMU shares and is not boot-critical. `KALLSYMS` off is the owner's choice (issue #130): a kernel trace shows raw addresses, which are decoded against the `System.map` of the same build. `docs/kernel-tiers.md` says both. *AC-7.*
3. **The initramfs split.** `build-initrd.sh` writes two compressed archives: the base (busybox, kmod, `/init` and the rest of the ported layout, no `lib/modules` tree) and the storage archive (the Tier-1 modules of `configs/initrd-modules.txt` with their dependency closure and the module-tree metadata `depmod` writes). The list gains `virtio_pci`, `vmw_pvscsi` and `hv_storvsc`, which were built in, and `ext4`, for `persist`. `initrd.img` is the base followed by the storage archive, byte for byte their concatenation, and `initrd-lowmem.img` is the base alone. Both are written with the deterministic cpio and compression options P02 set. *AC-3.*
4. **The `lowmem` entry.** `build-iso.sh` copies `initrd-lowmem.img` to `/boot/` and adds, after the `rescue` label:
   ```
   LABEL lowmem
       MENU LABEL Boot with 16 MB of RAM (IDE/CD only)
       KERNEL /boot/vmlinuz
       APPEND initrd=/boot/initrd-lowmem.img
   ```
   Every other ISOLINUX label and every GRUB entry keeps `/boot/initrd.img`, unchanged. `boot-test.py`'s `ENTRY_ISOLINUX` gains `"lowmem": []`, so G01's `entry` matrix boots it. *AC-4.*
5. **ext4 before the persistence mount.** With ext4 a module, `mount -t auto` tries only the filesystems the kernel already has, so `persist` fell back to tmpfs. `rootfs/init` runs `[ -n "$MODPROBE" ] && $MODPROBE -q ext4` before it mounts the persistence partition. *AC-5.*
6. **The `lowmem` mode.** `boot-test.py --mode lowmem` boots the BIOS machine of the `bios` mode under `-cpu 486` with `MODE_DEFAULT_RAM["lowmem"] = 16`, types the `lowmem` label with the serial console argument at the ISOLINUX prompt, as the `entry` mode does, and requires a shell, `uname -r` equal to `--kernel-version`, and `/proc/cmdline` naming `initrd-lowmem.img`. It logs the guest's `free` and the `MemTotal`, `Slab` and `SUnreclaim` lines of `/proc/meminfo`. `lowmem` joins `BOOT_MODES` and the `boot-test` job's `modes:` list. *AC-6.*
7. **Docs and ledger.** `README.md` line 6 says the CD boots a 486 with 16 MB through its `lowmem` entry, and that 8 MB is the aim. `docs/capabilities.md` gains a B04 row (the 16 MB boot: savedconfig, initramfs split, `lowmem` entry and mode). `scripts/check-migration.py --all` passes. *AC-7.*

## Risks
- **M04 first.** The config change is made on M04's 6.12.y and its refreshed savedconfig, not on 6.12.80; until M04 merges, this node does not start. The issue's figures were measured on 6.12.80.
- **`virtio`** failed on the issue's prototype CD rebuilt with `build-iso.sh`'s flags (OVMF never offered the disk as a boot option), and passed on a first CD with the same kernel, initramfs and squashfs. It is unexplained and appears to be in how the CD is mastered. AC-7 requires it; a failure is diagnosed from the recorded run, not retried away.
- **I2C.** The issue saw `olddefconfig` with GCC 15 turn on `I2C=m`, with the unchanged savedconfig too. B02's checks decide what is allowed; a fix that needs a judgment on the tier policy goes to the owner.
- **16 MB margin.** At 16 MB the prototype had 3708 kB available, and the kernel's own run-time allocations (Slab 3244 kB) were most of the rest. A later node that grows the kernel or the init path can break the mode; it then fails in CI, as it should.
- **A frozen test that lists the boot modes** (O01's or G01's) may need the new mode. If one does, the node stops and asks the owner before changing it, naming the lines, as M04 did.
- **`System.map`.** Whether the kernel package or the Build run keeps the `System.map` of the shipped kernel is unverified; if neither does, the node PR says where it is found.
