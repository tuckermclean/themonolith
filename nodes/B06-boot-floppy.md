## Purpose
Some machines have less than 16 MB of RAM or a BIOS that cannot boot a CD (most 486s and early Pentiums). After this node the CD carries a 1.44 MB boot floppy image, `/boot/floppy.img`. The floppy holds a loader: a small kernel with no networking and no modules, a minimal busybox and two scripts, which find the CD in any IDE/ATAPI drive and kexec a second small kernel, `-tiny`, stored on the CD, into the full system. With no CD it gives its own shell. Two boot modes prove the system reaches a shell from floppy and CD at 12 MB, and the floppy's shell at 8 MB.

## Standard mechanism
- **Kernels:** one kernel source and one ebuild build three kernels: the main one from the savedconfig, unchanged, and `-tiny` and `-floppy` from their committed `savedefconfig` files (`make ARCH=i386 tinyconfig` based, issue #130's), each with its own `LOCALVERSION`, so `-tiny` has its own module tree and no module is shared between configs (`MODVERSIONS` is off, so a mismatched module would load). Gap (SPEC §5): x86 always selects `PERF_EVENTS`, so no config drops perf events and hardware breakpoints (about 230 KB of code). → `files/tiny-no-perf.patch` adds `TINY_NO_PERF` under `EXPERT`; only `-tiny` and `-floppy` set it.
- **kexec:** Gentoo's `sys-apps/kexec-tools` from the pinned tree, static, with Portage's user patches (`/etc/portage/patches`, from `configs/portage/patches/`). Gap (SPEC §5): it will not place an initrd below 16 MB, and it reads the kernel and initrd into its own memory before `kexec_load()` copies them again, which at 8 MB runs out → `kexec-lowmem.patch` (the floor drops to the end of a non-relocatable kernel's unpack space, and both files are mapped instead of read). Big machines are unaffected.
- **The floppy:** SYSLINUX on FAT12, from the builder image as `build-iso.sh` uses it, `mkfs.vfat --invariant` and mtools, a deterministic cpio as `build-initrd.sh` writes. Gap (SPEC §5): dracut and genkernel do not fit 1.44 MB beside a kernel, and nothing finds a CD and kexecs. → the floppy's `/init` and `boot-cd`, issue #130's scripts, and a busybox built with only the applets they and the rescue shell use, packaged as the overlay's `sys-boot/monolith-floppy` (Gentoo has no such package), and `build-floppy.sh`, which assembles the image as `build-initrd.sh` assembles the initramfs.
- Custom code: the two patches, the two scripts and `build-floppy.sh`, the three gaps above. Two modes in `boot-test.py`, one test, `scripts/tests/boot-floppy.test.sh`.

## Risks
- **12 MB.** The issue recorded the floppy and CD at 12 MB to "press Enter for a shell" and called it the full system; whether the shell answers at 12 MB under QEMU's emulated 486 is unverified (the main kernel at 12 MB did not give one within 5 minutes). AC-6's way out stops for the owner.
- **The full system at 8 MB** is not a goal of this node: the `-tiny` kernel leaves 3504 kB `MemTotal` at 8 MB, and mounting the squashfs runs out. SPEC §10 tracks it.
- **Build time.** Three kernels from one ebuild lengthen the kernel build in every Build run and both of P02's builds; the node PR records the kernel's build time before and after.
- **Reproducibility.** The floppy is inside the ISO, so P02's gate needs it bit for bit. Whether the builder's SYSLINUX installer and mtools write the same bytes on every run, with the dates set, is unverified; AC-4 checks two runs, and P02's gate on the next tag checks the rest.
- **SYSLINUX version.** The issue used SYSLINUX 6.04; the builder image's Gentoo `sys-boot/syslinux` may differ. The floppy uses the builder's, as the ISO does.
- **The patches on 6.12.y and kexec-tools' pinned version.** The kernel patch was written against 6.12.80 and the kexec patch against 2.0.32; either may need a refresh in place on M04's kernel or the pinned tree's kexec-tools.
- **Drive coverage.** The loader has the legacy ISA/VLB ports plus PIIX, VIA, SiS, ALi, Opti, CMD640, RZ1000 and generic PCI IDE; QEMU's PIIX IDE is the only one CI boots. The floppy path has not been run in 86Box at real 486 speed, and that run stays by hand, not a criterion.
- **Workflow push.** The node changes `.github/workflows/build.yml` and `boot-test.yml`, which needs a token with the `workflow` scope to push (T-workflow-push-needs-pat).
- **First tag after the node.** If the node PR's Build run does not run P02's two from-source builds, the first tag's builds are the first run of `repro-build`'s `build-floppy.sh` line, and P02's equal ISO digests check the floppy there; AC-9 checks the recipe with `make -n` before then.
