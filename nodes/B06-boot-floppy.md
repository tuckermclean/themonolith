## Purpose
Some machines have less than 16 MB of RAM or a BIOS that cannot boot a CD (most 486s and early Pentiums). After this node the CD carries a 1.44 MB boot floppy image, `/boot/floppy.img`. The floppy holds a loader: a small kernel with no networking and no modules, a minimal busybox and two scripts, which find the CD in any IDE/ATAPI drive and kexec a second small kernel, `-tiny`, stored on the CD, into the full system. With no CD it gives its own shell. Two boot modes prove the system reaches a shell from floppy and CD at 12 MB, and the floppy's shell at 8 MB.

## Standard mechanism
- **Kernels:** one kernel source and one ebuild build three kernels: the main one from the savedconfig, unchanged, and `-tiny` and `-floppy` from their committed `savedefconfig` files (`make ARCH=i386 tinyconfig` based, issue #130's), each with its own `LOCALVERSION`, so `-tiny` has its own module tree and no module is shared between configs (`MODVERSIONS` is off, so a mismatched module would load). Gap (SPEC §5): x86 always selects `PERF_EVENTS`, so no config drops perf events and hardware breakpoints (about 230 KB of code). → `files/tiny-no-perf.patch` adds `TINY_NO_PERF` under `EXPERT`; only `-tiny` and `-floppy` set it.
- **kexec:** Gentoo's `sys-apps/kexec-tools` from the pinned tree, static, with Portage's user patches (`/etc/portage/patches`, from `configs/portage/patches/`). Gap (SPEC §5): it will not place an initrd below 16 MB, and it reads the kernel and initrd into its own memory before `kexec_load()` copies them again, which at 8 MB runs out → `kexec-lowmem.patch` (the floor drops to the end of a non-relocatable kernel's unpack space, and both files are mapped instead of read). Big machines are unaffected.
- **The floppy:** SYSLINUX on FAT12, from the builder image as `build-iso.sh` uses it, `mkfs.vfat --invariant` and mtools, a deterministic cpio as `build-initrd.sh` writes. Gap (SPEC §5): dracut and genkernel do not fit 1.44 MB beside a kernel, and nothing finds a CD and kexecs. → the floppy's `/init` and `boot-cd`, issue #130's scripts, and a busybox built with only the applets they and the rescue shell use, packaged as the overlay's `sys-boot/monolith-floppy` (Gentoo has no such package), and `build-floppy.sh`, which assembles the image as `build-initrd.sh` assembles the initramfs.
- Custom code: the two patches, the two scripts and `build-floppy.sh`, the three gaps above. Two modes in `boot-test.py`, one test, `scripts/tests/boot-floppy.test.sh`.

## Changes from the port
1. **The kernel patch.** `files/tiny-no-perf.patch`, issue #130's `floppy-noperf.patch` (8 files): `TINY_NO_PERF` under `EXPERT` in `arch/x86/Kconfig`; `PERF_EVENTS` and `HAVE_HW_BREAKPOINT` selected only without it; the debug-register and perf stubs it needs. Under the two small kernels debuggers cannot use the hardware debug registers (ptrace reads return 0, writes fail with `-EIO`). The main kernel does not set it, and its resolved config is unchanged. *AC-1.*
2. **Three kernels, one ebuild.** The kernel ebuild's next revision (D-revbump-on-overlay-change) applies the patch and builds, after the main kernel, `-tiny` (`/boot/vmlinuz-tiny`, modules in `/lib/modules/<version>-i486-monolith-tiny`) and `-floppy` (no modules, exported for `build-floppy.sh`) from the two defconfigs, with `olddefconfig`. Both small configs have `PHYSICAL_START=0x100000`, `PHYSICAL_ALIGN=0x100000`, `RELOCATABLE` unset, `TINY_NO_PERF=y`, `M486=y`, `ACPI` unset and gzip compression. `-tiny` also has `MODULES`, `NET`, `INET`, `UNIX`, `SYSVIPC`, `EPOLL`, `INOTIFY_USER`, `COMPAT_32BIT_TIME`, `FB_VESA`, `ISO9660_FS`, `SQUASHFS`, `OVERLAY_FS`, `BLK_DEV_LOOP`, `BLK_DEV_SR`, `ATA` and `PATA_LEGACY` built in, and as modules the ISA and PCI NICs, `SND_SB16`, `SND_SB8`, `SND_ES18XX`, `EXT4_FS`, `VFAT_FS`, `PPP`, `SLIP` and the mice of the issue's defconfig. `-floppy` has `KEXEC=y`, `MODULES` and `NET` unset, `ISO9660_FS`, `BLK_DEV_SR`, `ATA`, `ATA_PIIX`, `PATA_ALI`, `PATA_SIS`, `PATA_VIA`, `PATA_CMD640_PCI`, `PATA_OPTI`, `PATA_RZ1000`, `ATA_GENERIC` and `PATA_LEGACY` built in, and `SCSI_LOWLEVEL` unset. The two defconfigs join `savedconfig-cache.sh`'s tracked list, so an edit rebuilds the kernel. *AC-1, AC-2.*
3. **kexec-tools.** `sys-apps/kexec-tools` joins `world` and `versions.lock` at the pinned tree's version, static, built without xen, lzma and zlib (`package.use`), with `configs/portage/patches/sys-apps/kexec-tools/kexec-lowmem.patch` (issue #130's `kexec-lowmem.patch`). It gets a `run` row in `smoke-checks.txt` (`kexec --version`). *AC-3.*
4. **The floppy.** `sys-boot/monolith-floppy` builds busybox from the pinned tree's busybox source with a configuration that has `ash` with line editing and `FEATURE_SH_MATH`, `cat cp mv rm ls ln mkdir mknod echo printf test sleep sync uname chroot mount umount switch_root dmesg free ps kill reboot halt poweroff clear grep head tail more vi setsid cttyhack`, static, and installs it with issue #130's `/init` and `/bin/boot-cd` and `syslinux.cfg`. `build-floppy.sh` writes the floppy's initramfs (busybox, `/init`, `/bin/boot-cd`; deterministic cpio, gzip) and `output/floppy.img`: 1,474,560 bytes, FAT12 (`mkfs.vfat --invariant`, fixed volume ID and label), SYSLINUX installed, with `ldlinux.sys`, `ldlinux.c32`, `vmlinuz` (the `-floppy` kernel), `initrd.img` and `syslinux.cfg`, each dated `SOURCE_DATE_EPOCH`. `syslinux.cfg` has the `monolith`, `serial` (`console=tty0 console=ttyS0,115200n8`) and `rescue` labels, `monolith` the default. `boot-cd` tries `/dev/sr0` to `/dev/sr3` for up to a minute, mounts each as ISO9660, and on the one that has `/boot/vmlinuz-tiny` and `/boot/kexec` runs `kexec -l /media/boot/vmlinuz-tiny --initrd=/media/boot/initrd-tiny.img --append=<the boot options without initrd=, BOOT_IMAGE= and rescue>`, then `kexec -e -x`. With no CD, `/init` gives a shell where `boot-cd` searches again. `make floppy` runs it in the builder image; `make all` runs it before `iso`. *AC-4.*
5. **The CD.** `build-initrd.sh` also writes `initrd-tiny.img`: B04's base archive without kmod and with no module tree (the `-tiny` kernel has its storage drivers built in, and `/init` skips module loading when the initramfs has no module tree). `build-iso.sh` copies `vmlinuz-tiny`, `initrd-tiny.img`, the sysroot's `kexec` (as `/boot/kexec`) and `floppy.img` into `/boot/`. The ISO still fits P01's size budget. *AC-5.*
6. **The modes.** `boot-test.py --mode floppy-cd` extracts `/boot/floppy.img` from the ISO and boots QEMU with `-cpu 486 -m 12 -drive file=<floppy>,if=floppy,format=raw -cdrom <iso> -boot a`, types `serial` at the SYSLINUX prompt, and requires "press Enter for a shell", then a shell where `uname -r` is `<version>-i486-monolith-tiny`. `--mode floppy` boots the floppy alone at `-m 8`, and requires "No tHE m0n0LiTH CD found" and the floppy's shell, where `uname -r` is `<version>-i486-monolith-floppy`; it logs `free`. Both join `BOOT_MODES` and the `boot-test` job's `modes:` list. *AC-6, AC-7.*
7. **Docs and ledger.** `docs/boot-floppy.md`: what the floppy is for (less than 16 MB, or no CD boot), how to write it (`dd` to a 1.44 MB disk), its three labels and `boot-cd`, the boot options it passes on (`persist`, `toram`, `console=`), its limits (IDE/ATAPI CD drives only; no SCSI CD drives; no proprietary CD interfaces, which Linux dropped in 2.6.23), the hardware-breakpoint trade-off, and that the full system at 8 MB is not reached yet. `docs/kernel-tiers.md` names the three kernels and what each is for. `README.md` line 6 adds the boot floppy at 12 MB. `docs/capabilities.md` gains a B06 row. `scripts/check-migration.py --all` passes. *AC-8.*

## Risks
- **12 MB.** The issue recorded the floppy and CD at 12 MB to "press Enter for a shell" and called it the full system; whether the shell answers at 12 MB under QEMU's emulated 486 is unverified (the main kernel at 12 MB did not give one within 5 minutes). AC-6's way out stops for the owner.
- **The full system at 8 MB** is not a goal of this node: the `-tiny` kernel leaves 3504 kB `MemTotal` at 8 MB, and mounting the squashfs runs out. SPEC §10 tracks it.
- **Build time.** Three kernels from one ebuild lengthen the kernel build in every Build run and both of P02's builds; the node PR records the kernel's build time before and after.
- **Reproducibility.** The floppy is inside the ISO, so P02's gate needs it bit for bit. Whether the builder's SYSLINUX installer and mtools write the same bytes on every run, with the dates set, is unverified; AC-4 checks two runs, and P02's gate on the next tag checks the rest.
- **SYSLINUX version.** The issue used SYSLINUX 6.04; the builder image's Gentoo `sys-boot/syslinux` may differ. The floppy uses the builder's, as the ISO does.
- **The patches on 6.12.y and kexec-tools' pinned version.** The kernel patch was written against 6.12.80 and the kexec patch against 2.0.32; either may need a refresh in place on M04's kernel or the pinned tree's kexec-tools.
- **Drive coverage.** The loader has the legacy ISA/VLB ports plus PIIX, VIA, SiS, ALi, Opti, CMD640, RZ1000 and generic PCI IDE; QEMU's PIIX IDE is the only one CI boots. The floppy path has not been run in 86Box at real 486 speed, and that run stays by hand, not a criterion.
- **A frozen test that lists the boot modes** may need the new modes. If one does, the node stops and asks the owner before changing it, naming the lines.
